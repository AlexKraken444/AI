# Обучение языковой модели с нуля

Текущие Context 2/3 не освоили свободную речь. Предыдущая Context 3 получила всего
240 естественных диалоговых примеров; остальные 17 640 примеров — авторские задачи.
Изменение температуры или увеличение числа шагов на этом корпусе не исправляет
нехватку языковых данных. Новая ветка обучения не заменяет опубликованные веса,
пока качество ответов не проверено.

Проведён короткий GPU-тест: 15 363 840 параметров, 362 шага, бюджет обучающего
цикла 60 секунд. На ограниченном фрагменте train из 1 млн токенов выполнено
5 931 008 посещений токенов (с повторами). NLL на отдельных validation-документах
снизилась с 9.1503 до 5.4782. Это проверка работоспособности обучения, а не
обученная чат-модель. [Отчёт](gpu_pilot_report.json). Экспорт проверен численно.
Полная токенизация большого корпуса остановлена по переходу к короткой проверке;
для её завершения нужно повторить `prepare_language.py`. Минутный тест сохранён
локально в `training-output/gpu-pilot`, его веса не опубликованы на сайте.

## Что обучается

`scratch.py` использует наш causal Transformer со случайной инициализацией:
эмбеддинги, позиционные эмбеддинги, multi-head attention, FFN и выходной softmax.
PyTorch рассчитывает градиенты и операции на GPU; чужих весов и токенизаторов нет.
Архитектура по умолчанию: 6 слоёв, ширина 384, 6 голов, контекст 512, свой BPE
до 8192 токенов. Точное число параметров записывается в `config.json` запуска.

1. **Pretraining:** минимизируется `-log P(следующий токен | предыдущие токены)`
   на обычном тексте. Модель учит статистические закономерности языка.
2. **SFT:** продолжается обучение тех же весов на последовательностях
   «вопрос — ответ» с историей; ошибка считается только по токенам ответа.
   Текущий OASST-поднабор мал и сам по себе недостаточен для полноценного чата.
3. **Проверка:** новые вопросы, связность, соответствие вопросу, факты, память,
   арифметика и скорость. Validation NLL измеряет предсказание токенов,
   а не истинность или понимание. Вероятность выбранного токена не является
   вероятностью правильности ответа.

## Данные

Источник первого этапа: [Wikimedia Wikipedia](https://huggingface.co/datasets/wikimedia/wikipedia),
снимок `20231101.ru`, ревизия `b04c8d1ceb2f5cd4588862100d08de323dccfbaa`.
Лицензии источника: CC-BY-SA-3.0 / GFDL. У каждой статьи сохраняются `url`,
`title`, `id`; эти записи необходимо сохранять вместе с производными данными
для атрибуции. Корпус и веса не добавляются автоматически в Git.

Импорт потоковый по Parquet-батчам. Нормализованные полные дубликаты исключаются.
Разделение train/validation/test 98/1/1 по хешу документа происходит **до**
обучения токенизатора. Это не устраняет все близкие дубликаты: для масштабного
запуска потребуется дополнительная дедупликация. BPE обучается только на первых
2 млн символов train; это ограниченная выборка, её покрытие нужно проверять.
Manifest сохраняет хеши файлов, размеры и количество неизвестных токенов.
Токенизированные данные читаются через memmap, а не целиком в оперативную память.
Границы статей помечаются BOS/END; окна могут пересекать границы статей.
Личные чаты не используются.

## Запуск

Установить `requirements-train.txt` и CUDA-сборку PyTorch по
[официальной инструкции](https://pytorch.org/get-started/locally/).
В этом проекте также поддерживается изолированная установка в `.training-libs`.

```bash
python training/prepare_language.py --shards 1 --output training-data/language
python training/scratch.py --stage pretrain --data training-data/language --output training-output/language-v1 --device cuda --steps 10000 --max-seconds 600
```

`--max-seconds` ограничивает время обучающих шагов; подготовка, validation и
сохранение могут занять дополнительное время. Чтобы продолжить, повторить
**тот же** вызов с `--resume`. Сохраняются веса, AdamW, scaler, RNG, шаг и число
токенов. Изменение данных/токенизатора/расписания при resume отклоняется.
Результаты GPU могут не быть побитово идентичными между устройствами.

```bash
python training/prepare_data.py
python training/scratch.py --stage sft --data training-data --initialize training-output/language-v1 --output training-output/dialogue-v1 --device cuda --steps 1000 --lr 0.00003
python training/evaluate.py --model training-output/dialogue-v1 --output training-output/dialogue-v1/evaluation.json
python training/probe_chat.py --model training-output/dialogue-v1 --output training-output/dialogue-v1/chat-review.json
```

Не запускать SFT на незавершённом pretraining только ради получения «готового»
чекпойнта. Скрипт умеет это технически, но пригодность определяется проверками.
Длинные ответы SFT исключаются целиком с подсчётом, без ложного END при обрезании.
Для большего контекста архитектуру нужно выбрать **до** первого этапа.

Проверка инфраструктуры обучения (включая resume и маску SFT):
`python training/check_pipeline.py`. Обычные проверки приложения:
`python -m unittest discover -s tests -q` и `node --test tests/memory.test.cjs`.

`progress.json` содержит реальные NLL, шаги и число обработанных токенов.
`last.pt` нужен для продолжения; `model.npz` — лучший вариант на фиксированных
validation-окнах. После экспорта сравниваются PyTorch и NumPy logits.
Test split не участвует в подборе чекпойнта. Выборка validation-окон ограничена;
перед релизом нужна полная оценка и ручная проверка разнообразных диалогов.

## Генерация и Vercel

`Transformer.generate(..., temperature=0.7, top_p=0.9, seed=43)` выбирает следующий
токен из распределения после temperature/nucleus-фильтрации и снова вычисляет
вероятности с новым контекстом. `temperature=0` сохраняет жадное декодирование.
Новый sampling доступен для экспериментов; он не объявлен исправлением речи.

Vercel обслуживает сайт и NumPy inference; обучение запускается отдельно на GPU.
Большую модель нельзя автоматически считать подходящей для serverless:
перед заменой весов нужны замеры времени, памяти и размера пакета. Внешний API
не подключён. Новые checkpoints не копируются в `neural/` автоматически.
